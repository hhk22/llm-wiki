# 배포 가이드 v8

> v8 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

장애 리포트 #06에 따라 이미지 태그 형식을 service:git-sha로 제한하고 latest 태그를 금지했습니다. [1] [2] [3] [4]

## 변경 이유와 배경

- 알림이 구버전 템플릿으로 발송된 사고 이후에 변경되었습니다. [2] [5]
- latest 태그가 캐시된 구버전 이미지를 가리킨 원인으로 에러 코드 E-014가 발생했으며, git-sha 태그로 재배포하는 조치가 취해졌습니다. [3] [4]

## 변경 사항 및 v8 당시 규칙

- 이미지 태그 규칙으로 service:git-sha 형식만 허용하고 latest를 금지하도록 변경되었습니다. [1]
- 배포 도구는 Jenkins를 사용합니다. [6]
- 배포 명령은 Jenkins job deploy-staging에서 deploy-prod 순서로 실행합니다. [7]
- 롤백 명령은 Jenkins job rollback-prod를 실행합니다. [8]
- 배포 금지 시간은 금요일 오후입니다. [9]
- 승인자는 팀 리드와 SRE 온콜입니다. [10]
- 이전 버전은 배포 가이드 v7입니다. [11]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [12] [13]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [14]
  - [v2 변경 문서](v2.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [15] [16]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [17]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [18]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [19] [20]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [21]
  - [v6 변경 문서](v6.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [22] [23]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [24]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [25]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)
