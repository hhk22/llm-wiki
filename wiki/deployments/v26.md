# 배포 가이드 v26

> v26 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

feature flag 없는 대규모 변경 배포를 금지하도록 규칙이 변경되었습니다. [1] [2]

## 변경 사유

- DB 스키마가 함께 바뀌어 이전 버전이 동작하지 않아 catalog-api 서비스에 SEV1 장애가 발생한 이후 결정되었습니다. [3] [4]

## 대응 및 조치

- 핫픽스로 복구하고 feature flag 없는 대규모 변경을 금지하는 조치가 취해졌습니다. [5]

## v26 당시 규칙

- 배포 도구는 GitHub Actions를 사용합니다. [6]
- 배포 명령은 `deploy run --env prod`를 사용합니다. [7]
- 롤백 명령은 `deploy rollback --to <version>`을 사용하며 승인이 불필요합니다. [8]
- 배포 금지 시간은 목요일 오후, 공휴일 전날, 12/22~1/2 연말 동결입니다. [9]
- 승인자는 팀 리드와 서비스 오너입니다. [10]
- 이전 버전은 배포 가이드 v25입니다. [11]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [12] [13]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [14]
  - [v2 변경 문서](v2.md)
- v13 → v14: Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 → `deploy run --env prod` [15] [16]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [17]
  - [v14 변경 문서](v14.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [18] [19]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [20]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [21]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)
- v15 → v16: 금요일 오후 → 금요일 오후, 공휴일 전날 [22] [23]
  - 배포 금지 시간을 확대한다. 금요일 오후와 공휴일 전날에는 배포하지 않는다. [24]
  - [v16 변경 문서](v16.md)
- v21 → v22: 금요일 오후, 공휴일 전날 → 목요일 오후, 공휴일 전날 [25] [26]
  - 배포 금지 시간을 변경한다. 금요일 오후 대신 목요일 오후에 배포하지 않는다. 공휴일 전날은 유지한다. [27]
  - [v22 변경 문서](v22.md)
  - 장애 리포트 #18 이후 결정 [28]
  - [원인 사건: 장애 리포트 #18](../incidents/18.md)
- v24 → v25: 목요일 오후, 공휴일 전날 → 목요일 오후, 공휴일 전날, 12/22~1/2 연말 동결 [29] [30]
  - 연말 배포 동결 기간을 정한다. 12월 22일부터 1월 2일까지 배포하지 않는다. [31]
  - [v25 변경 문서](v25.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [32] [33]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [34]
  - [v6 변경 문서](v6.md)
- v13 → v14: Jenkins job `rollback-prod` 실행 → `deploy rollback --to <version>` [35] [36]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [17]
  - [v14 변경 문서](v14.md)
- v18 → v19: `deploy rollback --to <version>` → `deploy rollback --to <version>` (승인 불필요) [37] [38]
  - 롤백은 승인 없이 배포자가 즉시 실행할 수 있다. [39]
  - [v19 변경 문서](v19.md)
  - 장애 리포트 #14 이후 결정 [40]
  - [원인 사건: 장애 리포트 #14](../incidents/14.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [41] [42]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [43]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [44]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)
- v23 → v24: 팀 리드 + SRE 온콜 → 팀 리드 + 서비스 오너 [45] [46]
  - 배포 승인자를 변경한다. SRE 온콜 대신 서비스 오너가 승인한다. [47]
  - [v24 변경 문서](v24.md)

### 배포 도구

- v13 → v14: Jenkins → GitHub Actions (Jenkins 병행) [48] [49]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [17]
  - [v14 변경 문서](v14.md)
- v17 → v18: GitHub Actions (Jenkins 병행) → GitHub Actions [50] [51]
  - Jenkins를 완전히 종료한다. Jenkins 관련 절차는 더 이상 유효하지 않다. [52]
  - [v18 변경 문서](v18.md)
