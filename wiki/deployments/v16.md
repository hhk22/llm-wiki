# 배포 가이드 v16

> v16 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

배포 금지 시간이 금요일 오후와 공휴일 전날로 확대되었다. [1]

## 변경 사항 및 v16 당시 규칙

- 금요일 오후와 공휴일 전날에는 배포가 금지된다. [1] [2]
- 배포 도구는 GitHub Actions를 사용하며 Jenkins를 병행 운영한다. [3]
- 배포 및 롤백 명령어는 각각 `deploy run --env prod`와 `deploy rollback --to <version>`을 사용한다. [4] [5]
- 승인자는 팀 리드와 SRE 온콜이다. [6]
- 이전 버전은 배포 가이드 v15이다. [7]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [8] [9]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [10]
  - [v2 변경 문서](v2.md)
- v13 → v14: Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 → `deploy run --env prod` [11] [12]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [14] [15]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [16]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [17]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)
- v15 → v16: 금요일 오후 → 금요일 오후, 공휴일 전날 [18] [2]
  - 배포 금지 시간을 확대한다. 금요일 오후와 공휴일 전날에는 배포하지 않는다. [1]
  - [v16 변경 문서](v16.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [19] [20]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [21]
  - [v6 변경 문서](v6.md)
- v13 → v14: Jenkins job `rollback-prod` 실행 → `deploy rollback --to <version>` [22] [23]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [24] [25]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [26]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [27]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)

### 배포 도구

- v13 → v14: Jenkins → GitHub Actions (Jenkins 병행) [28] [29]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)
