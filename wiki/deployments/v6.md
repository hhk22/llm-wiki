# 배포 가이드 v6

> v6 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

배포 가이드 v6는 Jenkins job rollback-prod를 사용하는 롤백 절차를 명문화했습니다. [1]

## 변경 사항

- 롤백 절차로 Jenkins job rollback-prod를 사용하는 것이 명문화되었습니다. [1]

## v6 당시 규칙

- 배포 도구는 Jenkins를 사용합니다. [2]
- 배포 명령은 Jenkins job deploy-staging에서 deploy-prod 순서로 실행합니다. [3]
- 롤백 명령은 Jenkins job rollback-prod를 실행합니다. [4]
- 배포 금지 시간은 금요일 오후입니다. [5]
- 승인자는 팀 리드입니다. [6]
- 이전 버전은 배포 가이드 v5입니다. [7]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [8] [9]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [10]
  - [v2 변경 문서](v2.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [11] [12]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [13]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [14]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [15] [4]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [1]
  - [v6 변경 문서](v6.md)
