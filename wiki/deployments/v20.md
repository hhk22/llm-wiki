# 배포 가이드 v20

> v20 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

장애 리포트 #15 이후 배포 후 15분 동안 대시보드 모니터링이 의무화되었다. [1] [2]

## 변경 이유 및 장애 배경

- 장애 리포트 #15 당시 user-api 서비스 배포 2시간 뒤 메모리 부족으로 Pod가 반복 재시작되는 SEV2 장애가 발생했다. [3] [4] [5]
- 메모리 누수가 배포 직후 헬스체크에서는 드러나지 않아(에러 코드 E-015) 롤백을 수행하고 배포 후 모니터링을 의무화하는 후속 조치가 배포 가이드 v20에 반영되었다. [6] [7] [8]

## v20 당시 규칙

- 배포 도구는 GitHub Actions이며 배포 명령은 `deploy run --env prod`이다. [9] [10]
- 롤백 명령은 `deploy rollback --to <version>`으로 승인이 불필요하다. [11]
- 배포 금지 시간은 금요일 오후와 공휴일 전날이며, 승인자는 팀 리드와 SRE 온콜이고 이전 버전은 배포 가이드 v19이다. [12] [13] [14]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [15] [16]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [17]
  - [v2 변경 문서](v2.md)
- v13 → v14: Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 → `deploy run --env prod` [18] [19]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [20]
  - [v14 변경 문서](v14.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [21] [22]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [23]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [24]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)
- v15 → v16: 금요일 오후 → 금요일 오후, 공휴일 전날 [25] [26]
  - 배포 금지 시간을 확대한다. 금요일 오후와 공휴일 전날에는 배포하지 않는다. [27]
  - [v16 변경 문서](v16.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [28] [29]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [30]
  - [v6 변경 문서](v6.md)
- v13 → v14: Jenkins job `rollback-prod` 실행 → `deploy rollback --to <version>` [31] [32]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [20]
  - [v14 변경 문서](v14.md)
- v18 → v19: `deploy rollback --to <version>` → `deploy rollback --to <version>` (승인 불필요) [33] [34]
  - 롤백은 승인 없이 배포자가 즉시 실행할 수 있다. [35]
  - [v19 변경 문서](v19.md)
  - 장애 리포트 #14 이후 결정 [36]
  - [원인 사건: 장애 리포트 #14](../incidents/14.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [37] [38]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [39]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [40]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)

### 배포 도구

- v13 → v14: Jenkins → GitHub Actions (Jenkins 병행) [41] [42]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [20]
  - [v14 변경 문서](v14.md)
- v17 → v18: GitHub Actions (Jenkins 병행) → GitHub Actions [43] [44]
  - Jenkins를 완전히 종료한다. Jenkins 관련 절차는 더 이상 유효하지 않다. [45]
  - [v18 변경 문서](v18.md)
