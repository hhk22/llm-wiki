# 배포 가이드 v21

> v21 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

카나리 배포가 모든 서비스로 확대되어 10퍼센트에서 50퍼센트를 거쳐 100퍼센트 순서로 진행하도록 변경되었다. [1]

## 변경 사항

- 카나리 배포를 모든 서비스로 확대하고 10%에서 50%를 거쳐 100% 순서로 진행하도록 변경되었다. [1]

## v21 당시 규칙

- 배포 도구는 GitHub Actions를 사용한다. [2]
- 배포 명령은 `deploy run --env prod`이다. [3]
- 롤백 명령은 `deploy rollback --to <version>`이며 승인이 불필요하다. [4]
- 배포 금지 시간은 금요일 오후와 공휴일 전날이다. [5]
- 승인자는 팀 리드와 SRE 온콜이다. [6]
- 이전 버전은 배포 가이드 v20이다. [7]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [8] [9]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [10]
  - [v2 변경 문서](v2.md)
- v13 → v14: Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 → `deploy run --env prod` [11] [12]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [14] [15]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [16]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [17]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)
- v15 → v16: 금요일 오후 → 금요일 오후, 공휴일 전날 [18] [19]
  - 배포 금지 시간을 확대한다. 금요일 오후와 공휴일 전날에는 배포하지 않는다. [20]
  - [v16 변경 문서](v16.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [21] [22]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [23]
  - [v6 변경 문서](v6.md)
- v13 → v14: Jenkins job `rollback-prod` 실행 → `deploy rollback --to <version>` [24] [25]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)
- v18 → v19: `deploy rollback --to <version>` → `deploy rollback --to <version>` (승인 불필요) [26] [27]
  - 롤백은 승인 없이 배포자가 즉시 실행할 수 있다. [28]
  - [v19 변경 문서](v19.md)
  - 장애 리포트 #14 이후 결정 [29]
  - [원인 사건: 장애 리포트 #14](../incidents/14.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [30] [31]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [32]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [33]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)

### 배포 도구

- v13 → v14: Jenkins → GitHub Actions (Jenkins 병행) [34] [35]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [13]
  - [v14 변경 문서](v14.md)
- v17 → v18: GitHub Actions (Jenkins 병행) → GitHub Actions [36] [37]
  - Jenkins를 완전히 종료한다. Jenkins 관련 절차는 더 이상 유효하지 않다. [38]
  - [v18 변경 문서](v18.md)
