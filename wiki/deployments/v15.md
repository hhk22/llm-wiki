# 배포 가이드 v15

> v15 시점 · 과거 버전

현재 적용 기준은 [배포 가이드 v30](v30.md)에서 확인한다.

GitHub Actions 오류 수정 및 deployments: write 권한 추가를 반영한 배포 가이드 v15이다. [1] [2]

## 변경 내용 및 이유

- GitHub Actions 오류 수정 (E-021 워크플로 권한 부족)으로 워크플로에 `deployments: write` 권한을 추가한다. [1]
- 장애 리포트 #12 이후 결정되었다. [2] [3] [4]

## v15 당시 규칙

- 배포 도구는 GitHub Actions (Jenkins 병행)이다. [5]
- 배포 명령은 `deploy run --env prod`이다. [6]
- 롤백 명령은 `deploy rollback --to <version>`이다. [7]
- 배포 금지 시간은 금요일 오후이다. [8]
- 승인자는 팀 리드 + SRE 온콜이다. [9]
- 이전 버전은 배포 가이드 v14이다. [10]

## 규칙별 변경 이력

이 페이지의 버전까지 확인된 변경이다.

### 배포 명령

- v1 → v2: Jenkins job `deploy-prod` 실행 → Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 [11] [12]
  - staging 배포 단계를 추가한다. prod 배포 전 staging에 먼저 배포한다. [13]
  - [v2 변경 문서](v2.md)
- v13 → v14: Jenkins job `deploy-staging` → `deploy-prod` 순서로 실행 → `deploy run --env prod` [14] [15]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [16]
  - [v14 변경 문서](v14.md)

### 배포 금지 시간

- v4 → v5: 없음 → 금요일 오후 [17] [18]
  - 배포 금지 시간을 추가한다. 금요일 오후에는 prod 배포를 하지 않는다. [19]
  - [v5 변경 문서](v5.md)
  - 장애 리포트 #03 이후 결정 [20]
  - [원인 사건: 장애 리포트 #03](../incidents/03.md)

### 롤백 명령

- v5 → v6: 이전 빌드를 `deploy-prod`로 재실행 → Jenkins job `rollback-prod` 실행 [21] [22]
  - 롤백 절차를 명문화한다. Jenkins job `rollback-prod`를 사용한다. [23]
  - [v6 변경 문서](v6.md)
- v13 → v14: Jenkins job `rollback-prod` 실행 → `deploy rollback --to <version>` [24] [25]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [16]
  - [v14 변경 문서](v14.md)

### 승인자

- v6 → v7: 팀 리드 → 팀 리드 + SRE 온콜 [26] [27]
  - 배포 승인자를 변경한다. 팀 리드와 SRE 온콜 두 명의 승인이 필요하다. [28]
  - [v7 변경 문서](v7.md)
  - 장애 리포트 #05 이후 결정 [29]
  - [원인 사건: 장애 리포트 #05](../incidents/05.md)

### 배포 도구

- v13 → v14: Jenkins → GitHub Actions (Jenkins 병행) [30] [31]
  - 배포 도구를 GitHub Actions로 전환한다. Jenkins는 병행 운영한다. [16]
  - [v14 변경 문서](v14.md)
