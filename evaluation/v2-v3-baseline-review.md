# v3 설계 전 v2 기준선 측정

**현재 규칙과 변경 이유를 함께 묻는 질문에서도 v2가 필요한 내용을 답했다.** 이 사례를 RAG의 종합 답변 실패나 Wiki 전환의 품질 개선 근거로 사용할 수 없다.

## 재현 조건

- 코드: `88112dc1401ae502de34e68a59b91f4b58778604`. 서비스 코드는 변경하지 않았다.
- 질문: [v3-baseline-questions.json](./v3-baseline-questions.json). 기존 20문항은 변경하지 않았으며 이번 실행에서 전체 20문항을 재평가하지 않았다.
- 결과: [results-v2-v3-baseline.json](./results-v2-v3-baseline.json). 실행 시각, 원본·질문·측정 스크립트 해시, 선택 청크, 참조 보강 전후 결과, 실제 답변, 시간, SDK 토큰 사용량을 보관했다.
- 새 로컬 색인: 문서 120개, 청크 150개, `gemini-embedding-2` 768차원. 원본과 DB의 누락·중복·해시·본문 불일치 0건.
- PostgreSQL 17.11, pgvector 0.8.6. 기존 서버 DB의 벡터를 복사한 재평가는 아니다.
- 기본 벡터 검색, 질문별 버전 범위 판단, 문서 Top 3, 문서당 최대 2개 청크, 명시된 원인 장애 참조 1단계.
- 생성 모델: `gemini-3.6-flash`, temperature 0. 기존 답변 프롬프트와 재시도 함수를 그대로 사용했다.
- 기대 답·문서 ID는 판정용이며 임베딩·검색·생성 입력에 전달하지 않았다.
- 질문별 1회 실행. 응답 시간은 임베딩·DB 검색·참조 조회·생성을 포함하고, 호출 제한을 위한 질문 사이 대기는 제외한다.

```bash
python scripts/measure_v2_baseline.py --output evaluation/results-v2-v3-baseline-new.json
```

`.env`에 DB 연결과 Gemini 설정이 필요하다. 기존 결과를 덮어쓰지 않도록 새 출력 경로를 지정한다. 로컬 실행에서는 Windows가 신뢰하는 인증서를 묶어 `SSL_CERT_FILE`로 지정했고, 인증서 검증을 유지했다.

## 답변과 근거 판정

| ID | 판정 | 실제 근거와 확인 내용 |
| --- | --- | --- |
| `control-cause` | 핵심 답변·근거 충족 | v22의 변경 이유와 장애 #18 원문으로 정산 배치·배포 충돌을 설명했다. |
| `current-and-cause` | 핵심 답변·근거 충족 | FAQ Q02가 현재 금지 시간 세 항목을, v22·장애 #18이 변경과 원인을 뒷받침한다. |
| `followup-raw` | 기대 내용 일치, 대화 맥락 처리 미검증 | 대화 이력을 받지 않고 v30·v16·v25를 검색했다. 과거 금요일 오후·공휴일 전날 금지는 v16에 있으나, 질문의 대상을 앞선 대화에서 해석한 결과는 아니다. |
| `followup-explicit-diagnostic` | 명시적 질문의 답변·근거 충족 | v22 변경 항목에 금요일 오후에서 목요일 오후로 변경하고 공휴일 전날은 유지한다는 근거가 있다. 사람이 대상을 명시한 질문이며 자동 맥락 처리 조건 B가 아니다. |

문서 ID가 예상 목록과 같다는 이유만으로 성공 처리하지 않았고, 예상 ID가 없다는 이유만으로 실패 처리하지도 않았다. `current-and-cause`에는 v30이 없지만 FAQ Q02가 현재 규칙을 담고 있다. 반대로 `followup-raw`의 정답 내용 일치는 대화 기능의 성공을 입증하지 않는다.

첫 질문의 답변은 현재 규칙 문장에 `[1][3]`을 붙였다. `[1]` FAQ Q02는 세 항목 전체를, `[3]` v22는 목요일 오후·공휴일 전날을 뒷받침한다. 연말 동결의 근거는 `[1]`이다. 이 판정은 핵심 내용이 인용된 원본으로 뒷받침되는지 확인한 것으로, 모든 개별 인용이 문장 전체를 지지한다는 뜻은 아니다.

## 시간과 토큰

| ID | 응답 시간 | 생성 입력 | 생성 출력 | 사고 토큰 | 생성 총 토큰 |

질문마다 임베딩 1회·생성 1회가 성공했고 재시도는 없었다. 임베딩 응답은 토큰 사용량을 제공하지 않아 `null`로 기록했다. 위 표는 생성 응답의 SDK 사용량이며, 색인 비용과 임베딩 비용을 합친 총비용 또는 금액이 아니다. 단회 실행 시간으로 속도 개선이나 비용 절감을 주장하지 않는다.

## 다음 비교

1. 기존 v2가 답한 현재 규칙·변경 이유를 v3에서도 원본 근거와 함께 유지한다.
2. 후속 질문은 같은 대화 이력·질문 해석 방식·답변 모델을 제공한 v2와 v3를 비교한다. 이번 실행은 그 비교를 완료한 것이 아니다.
3. Wiki 생성·검토 비용과 질의 비용을 따로 기록한다. 반복 질문에서 사전 종합의 이점이 확인되는지 측정한다.
4. Wiki 생성 입력에 이 평가 질문과 정답을 넣지 않는다. 결과를 보고 질문을 바꿔 v2의 실패를 유도하지 않는다.

Wiki 기능과 우월성은 아직 검증하지 않았다.
