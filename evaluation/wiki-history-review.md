# v3 생성 Wiki의 시점·변경 이력·상충 검토

초기 생성물 `0033be0`의 페이지·링크·목차 33개 작업 결과를 재검증해 재사용하고, 배포 원본에서 이력을 계산해 Markdown을 다시 생성했다. 원본 120개와 기존 검색·답변 API는 변경하지 않았다.

## 무엇을 바꿨는가

| 대상 | 반영한 내용 |
| --- | --- |
| [과거 v22](../wiki/deployments/v22.md) | `현재 규칙` → `v22 당시 규칙`, 최신 v30 링크, v22 이후 변경은 이력에서 제외 |
| [최신 v30](../wiki/deployments/v30.md) | 규칙별 전후 값·출처, 변경 버전 v22·v25 및 원인 장애 #18로 직접 이동 |
| 이력 추출 | 연속 배포 버전의 `현재 규칙` 항목 비교. 코드 밖 공백 서식 차이는 제외하고 코드 안의 문자와 단어 경계는 보존 |
| 원인 사건 | 해당 변경 버전의 `이유` 항목에 명시된 장애만 연결 |
| 상충 후보 | 배포 가이드와 이를 참조하는 원본의 본문·메타데이터·변경 정보를 LLM에 전달해 검토 |
| 상충 표시 | 최신 가이드와 해당 원본의 Wiki에 `확인 필요`, 양쪽 원문·출처·시점 불확실성 표시. 정답을 자동 선택하지 않음 |

페이지 렌더링에서 시점과 이력을 적용하므로 생성된 Markdown을 직접 편집하지 않는다. 동일 원본의 같은 규칙에 서로 다른 값이 중복되면 코드로 표시한다. LLM 검토에는 서로 다른 원본 두 개 이상의 실제 인용을 요구하며, 서로 다른 배포 버전끼리의 비교만으로 충돌을 주장하면 거절한다.

## 확인 결과

| 검사 | 결과 |
| --- | --- |
| 생성물 | 본문 120개·목차 5개 유지 |
| 규칙 항목의 변경 | 14건. 한 버전이 여러 항목을 변경할 수 있음 |
| 실제 원본 상충 검토 | 67개 원본, 모델이 반환한 후보 0건 |
| 링크 검사 | 2,166개 통과 |
| 기존 생성 본문의 근거 인용 | 978개 원문 일치; 이력 출처는 원본에서 재계산하고 렌더링 전체를 대조 |
| 테스트 | 146개 통과, 건너뜀 없음, DB 연동 포함 |
| 정적 검사 | Ruff 통과 |

초기 구현에서 공백 차이를 변경으로 잡은 두 항목을 제외했다. 상충 검토는 보강 과정에서 총 2회 호출했으며, 보고된 토큰은 입력 38,815·출력 1,372·합계 40,187이다. 이전 검토 결과와 프롬프트는 manifest의 `superseded_jobs` 및 호출 기록에 남겼다. 아래 별도 실험의 사용량은 이 합계에 포함하지 않는다.

## 실제 모델로 실행한 인위적 상충 사례

평가 입력만 메모리에서 수정했고 `sources/`는 보존했다. 모델은 `gemini-3.5-flash-lite`, temperature는 0이며 각 조건을 1회 실행했다.

| 조건 | 원본 구성 | 결과 |
| --- | --- | --- |
| 정상 이력 | 가이드 v21·v22·v24·v25·v30 + 원본 FAQ Q02 | 후보 0건 |
| 반대 주장 | 같은 구성에서 FAQ Q02를 “현재 목요일 오후에는 배포할 수 있다”로 수정 | FAQ Q02와 v30을 근거로 후보 1건 |

프롬프트·스키마·응답·토큰은 [실험 JSON](wiki-history-conflict-probe.json)에, 이력 근거와 오프라인 검증 집계는 [검증 JSON](wiki-history-validation.json)에 보관했다. 단위 테스트에서도 상충을 포함한 양쪽 출처가 `확인 필요`에 표시되고 기존 규칙을 덮어쓰지 않는지 확인한다.

## 범위와 한계

- 자동 이력은 **연속 버전이며, `현재 규칙` 절에 같은 이름으로 존재하는 항목**을 대상으로 한다. 빠진 버전·필드의 변경 시점을 추측하지 않는다. 자유 형식의 모든 변경 문장을 자동으로 분류하는 기능은 아니다.
- 본문의 대표 표현 `현재 규칙`·`현재 배포`를 과거 버전에 맞게 표시한다. 모든 자연어 시점 표현을 자동으로 이해한다는 의미는 아니다.
- FAQ의 관련 버전 번호와 수정 날짜를 적용 시점으로 단정하지 않는다. 상충 후보의 의미·범위·우선순위는 사람이 원본과 대조해야 한다.
- 후보 0건은 상충이 없다는 증명이 아니다. 단회 인위적 실험도 전수 탐지 성능이나 Wiki 답변 품질의 증명이 아니다.

다음 단계는 Wiki 기반 질의·후속 질문 구현과 기존 `vector`·`hybrid`·`keyword` 대비 동일 조건 비교다.
